# ربات قیمت آنلاین (Price Bot)

این پروژه از ساعت ۹ صبح تا ۹ شب، هر ۲ ساعت یک‌بار (کاملاً رایگان، با
GitHub Actions) به‌صورت چرخشی به کانال تلگرام شما پست می‌فرسته. **هر
دسته‌بندی قیمت، پست تلگرام مستقل خودش رو داره** (نه یک پیام ترکیبی).

| ساعت (تهران) | نوع | تعداد پست | جزئیات |
|---|---|---|---|
| ۰۹:۰۰ | 📊 قیمت | ۶ پست جدا | ارز، ارز دیجیتال، فلزات گرانبها، گوشی موبایل، کالاهای اساسی، لوازم یدکی خودرو |
| ۱۱:۰۰ | 📰 مقاله | ۱ پست | یک مقاله (تیتر + خلاصه + لینک) |
| ۱۳:۰۰ | 📰 مقاله | ۱ پست | مقاله بعدی |
| ۱۵:۰۰ | 📊 قیمت | ۵ پست جدا | لپ‌تاپ، موبایل، پوشاک، هایپرمارکت، لوازم فروشگاهی |
| ۱۷:۰۰ | 📰 مقاله | ۱ پست | مقاله بعدی |
| ۱۹:۰۰ | 📊 قیمت | ۵ پست جدا | صوتی‌تصویری، تجهیزات کافی‌شاپ، کوهنوردی، سفر و کمپینگ، لوازم خانه و آشپزخانه |
| ۲۱:۰۰ | 📰 مقاله | ۱ پست | مقاله بعدی |

**جمع کل روزانه: ۲۰ پست** (۱۶ پست قیمت + ۴ پست مقاله)

هر ۱۶ دسته‌بندی (۶ اصلی + ۱۰ اضافه) دقیقاً **یک‌بار در روز** پست میشن؛
هیچ دسته‌ای در همون روز تکرار نمیشه. بین پست‌های پیاپی هم ۱.۵ ثانیه
فاصله گذاشته شده تا محدودیت نرخ ارسال تلگرام رعایت بشه.

## ساختار پروژه

```
price-bot/
├── scraper_prices.py       # استخراج 6 دسته اصلی (ارز، ارز دیجیتال، فلزات، موبایل، کالای اساسی، لوازم یدکی) از صفحه اصلی
├── scraper_categories.py   # استخراج محصولات از 10 صفحه دسته‌بندی اختصاصی (لپ‌تاپ، پوشاک، هایپرمارکت و ...)
├── scraper_articles.py     # استخراج آخرین مقالات + خلاصه
├── scheduler.py             # تعیین نوع پست بر اساس ساعت + حافظه مقالات پست‌شده
├── telegram_notifier.py    # ارسال پیام به تلگرام
├── main.py                  # اجرای کل فرآیند و ساخت پست‌های جدا برای هر دسته
├── state.json                # حافظه مقالات پست‌شده امروز - خودکار بروزرسانی میشه
├── requirements.txt
└── .github/workflows/daily-post.yml   # زمان‌بند اجرای ۷ بار در روز
```

## مرحله ۱ — ساخت ربات تلگرام

1. در تلگرام به [@BotFather](https://t.me/BotFather) پیام بدید.
2. دستور `/newbot` رو بزنید و طبق مراحل، یک نام و یوزرنیم برای ربات انتخاب کنید.
3. در انتها یک **توکن** به شما میده، شبیه:
   `123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`
   این توکن رو جایی امن نگه دارید (لازمش داریم).
4. ربات ساخته‌شده رو به کانالتون (**قیمت آنلاین**) اضافه کنید و
   نقش **ادمین** با دسترسی «ارسال پیام» بهش بدید.

## مرحله ۲ — پیدا کردن Chat ID کانال

- اگر کانال شما **پابلیک** هست، همون یوزرنیم کافیه، مثلاً: `@qeymatonline`
- اگر **خصوصی** هست:
  1. یک پیام تستی در کانال بفرستید.
  2. به این آدرس در مرورگر برید (به‌جای `<TOKEN>` توکن ربات رو بذارید):
     `https://api.telegram.org/bot<TOKEN>/getUpdates`
  3. در خروجی JSON دنبال `"chat":{"id": -100xxxxxxxxxx` بگردید؛ همون عدد Chat ID شماست.

## مرحله ۳ — ساخت ریپازیتوری در گیت‌هاب

1. یک ریپازیتوری جدید (می‌تونه Private باشه) در گیت‌هاب بسازید.
2. تمام فایل‌های این پوشه رو داخلش push کنید:

```bash
cd price-bot
git init
git add .
git commit -m "Initial commit: price & article bot"
git branch -M main
git remote add origin https://github.com/<YOUR_USERNAME>/<YOUR_REPO>.git
git push -u origin main
```

## مرحله ۴ — تنظیم Secrets در گیت‌هاب

در ریپازیتوری خودتون:
`Settings → Secrets and variables → Actions → New repository secret`

دو مقدار زیر رو اضافه کنید:

| Name                 | Value                                  |
|----------------------|-----------------------------------------|
| `TELEGRAM_BOT_TOKEN`  | توکنی که از BotFather گرفتید            |
| `TELEGRAM_CHAT_ID`    | یوزرنیم کانال یا Chat ID عددی            |

## مرحله ۵ — فعال‌کردن اجازه commit (فقط یک‌بار، ضروری)

چون ربات بعد از هر پست مقاله، فایل `state.json` رو خودش commit می‌کنه،
باید به Actions اجازه‌ی نوشتن روی ریپازیتوری رو بدید:

`Settings → Actions → General → Workflow permissions`
گزینه‌ی **Read and write permissions** رو انتخاب و Save کنید.

## مرحله ۶ — تست دستی (اختیاری)

از تب **Actions** ریپازیتوری، روی workflow با نام
`Scheduled Price & Article Posts` کلیک کنید و دکمه **Run workflow** رو بزنید.
می‌تونید در فیلد `force_slot` مقدار `price` یا `article` رو وارد کنید تا
بدون توجه به ساعت فعلی، همون نوع پست تست بشه؛ خالی بذارید یعنی بر اساس
ساعت فعلی تصمیم بگیره.

از این به بعد، هر ۲ ساعت (طبق جدول بالا) به‌صورت خودکار اجرا میشه.
زمان‌های اجرا رو می‌تونید در فایل `.github/workflows/daily-post.yml`
(خطوط `cron`) و ترتیب قیمت/مقاله رو در `scheduler.py` (دیکشنری `SCHEDULE`)
تغییر بدید.

> ⚠️ نکته: GitHub Actions گاهی cron رو با چند دقیقه تاخیر اجرا می‌کنه
> (معمولاً بین ۰ تا ۱۵ دقیقه)؛ این طبیعیه و روی عملکرد ربات تاثیری نداره.

```bash

```

## نکات و شخصی‌سازی

- **تغییر ساعت‌ها یا ترتیب دسته‌ها**: فایل `scheduler.py` (`SCHEDULE`،
  `PRICE_SLOT_HOURS`) و `main.py` (`ALL_CATEGORIES`،
  `PRICE_SLOT_CHUNK_SIZES`). اگه ساعت‌ها رو عوض کردید، حتماً `cron`های
  متناظر رو هم در `.github/workflows/daily-post.yml` بروزرسانی کنید
  (تهران = UTC + 3:30).
- **اضافه‌کردن دسته‌بندی جدید**: یک ورودی به دیکشنری `CATEGORY_PAGES`
  در `scraper_categories.py` اضافه کنید (نام + آدرس صفحه)، بعد یک
  ورودی متناظر (عنوان نمایشی + ایموجی) به `CATEGORY_INFO` در `main.py`
  اضافه کنید و آخرش `PRICE_SLOT_CHUNK_SIZES` رو طوری تنظیم کنید که
  جمعش با تعداد کل دسته‌ها (`len(ALL_CATEGORIES)`) برابر بمونه.
- **تعداد محصول نمایش‌داده‌شده در هر دسته‌ی اضافه**: متغیر
  `PRODUCTS_PER_CATEGORY` در `main.py` (پیش‌فرض ۶).
- **فاصله بین پست‌های پیاپی**: متغیر `DELAY_BETWEEN_POSTS_SECONDS` در
  `main.py` (پیش‌فرض ۱.۵ ثانیه).
- **تعداد مقالات کاندید برای بررسی تکراری نبودن**: متغیر
  `ARTICLE_CANDIDATES_LIMIT` در `main.py`.
- **اضافه‌کردن دسته لپ‌تاپ یا سایر کالاها**: در حال حاضر «ویترین زنده بازار»
  صفحه اصلی این دسته‌ها رو نداره؛ برای این‌کار باید یک تابع مشابه
  `scraper_prices.py` برای صفحات دسته‌بندی (مثل `/Digital-appliances/laptop`)
  نوشته بشه. اگه لازم شد بگید تا اون بخش رو هم اضافه کنم.
- **آنالیز رقبا**: چون این ربات ساختار مستقل داره، به همین سادگی می‌تونید
  یک `scraper_competitor.py` جدا با همین منطق (fetch + BeautifulSoup) برای
  سایت رقیب بسازید و قیمت‌ها رو کنار قیمت خودتون مقایسه کنید. اگه آدرس
  دقیق رقبا و ساختار HTML صفحه‌شونو بدید، همین الان می‌نویسمش.

## محدودیت‌ها

- `robots.txt` سایت gheimatonline.com دسترسی ابزارهای خودکار (مثل کرالرهای
  Claude) رو محدود کرده؛ اما این محدودیت مخصوص بعضی سرویس‌ها بوده و اجرای
  این اسکریپت از سرورهای GitHub Actions معمولاً بدون مشکل کار می‌کنه. اگر
  در اجرا با خطای دسترسی مواجه شدید، لازمه با تیم فنی سایت خودتون هماهنگ
  کنید که User-Agent این ربات (`User-Agent` تعریف‌شده در `scraper_prices.py`)
  رو در فایروال/کلادفلر مسدود نکنن.
